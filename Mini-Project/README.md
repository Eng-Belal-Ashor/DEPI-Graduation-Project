## 📌 Project Overview

This project focuses on **Exploratory Testing** of an ATM Simulator application.

Our goal was to explore the application, understand its behavior, identify unexpected results, and discover potential defects through practical testing.

Instead of following only predefined test cases, we used an exploratory approach where learning, testing, and analyzing happened together.

This project was completed as a team mini-project as part of our Software Testing learning journey.

## 🎯 Project Objectives

The main objectives of this project were:

- 🔍 Apply Exploratory Testing in a practical project.
- 🏧 Understand the ATM Simulator's functionality and behavior.
- 🧪 Explore different features and user interactions.
- 🐞 Identify unexpected behaviors and potential defects.
- 💻 Compare testing results across different environments.
- 🤝 Practice teamwork, communication, and collaborative testing.
- 📝 Document findings using Session Logs and Bug Reports.

## 🔬 Testing Approach

We followed an exploratory testing approach supported by a Test Charter.

### 1️⃣ Research & Application Selection

Before starting the project, we researched Exploratory Testing and explored possible applications for testing.

We considered two options:

- 🏧 ATM Simulator
- 📝 To-Do List Application

After comparing the options and discussing the challenges, we decided to work with an ATM Simulator.

### 2️⃣ 📋 Test Charter Preparation

Before testing, we prepared a Test Charter to define our testing direction.

The charter helped us identify:

- 🎯 Testing Objectives
- 📌 Testing Scope
- 🔎 Main Areas to Explore
- 🧭 Testing Approach
- ⏱️ Session Time and Focus

### 3️⃣ 💻 Environment Setup

Each team member prepared a different testing environment using their own device, operating system, and browser.

This allowed us to explore the application under different conditions.

### 4️⃣ 🤝 Collaborative Exploratory Testing Session

We conducted a shared **30-minute testing session** through Microsoft Teams.

During the session:

- 🔍 Each member explored the application.
- 🧪 We tried different actions and scenarios.
- 💬 We shared unexpected behaviors with the team.
- 🔄 Other members attempted to reproduce the reported findings.
- 💡 We exchanged ideas and explored additional possibilities.

### 5️⃣ 🧐 Reviewing & Validating Findings

After completing the session, we discussed the findings together.

We reviewed each reported behavior to determine whether it was:

- 🐞 A confirmed Bug.
- ✨ A possible Enhancement.
- 💭 A misunderstanding or incorrect interpretation of the application behavior.

This step helped us avoid reporting every unexpected observation as a defect without proper discussion.

### 6️⃣ 📝 Documentation

After reviewing the findings, we organized our testing results and documented the confirmed issues.

Our main documentation included:

- 📋 **Test Charter:** Defines the testing objectives and scope.
- 📒 **Session Logs:** Records testing activities, observations, and environment details.
- 🐞 **Bug Reports:** Documents identified defects with reproduction steps, expected results, actual results, severity, and priority.
- 📸 **Evidence:** Screenshots and video recordings supporting the findings.
